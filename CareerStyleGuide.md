# Career Style Guide

## Purpose

This document defines writing conventions for resumes, portfolio documents, interview materials, engineering cases, and cover letters stored in this repository.

---

## General Principles

- Engineering First: describe work with technical clarity, accuracy, and attention to real engineering decisions.
- ATS Friendly: use clear section names, standard terminology, and readable formatting that applicant tracking systems can parse.
- Human Friendly: make documents easy for recruiters, hiring managers, and technical interviewers to understand.
- Results over Responsibilities: focus on outcomes, impact, and delivered value instead of generic task descriptions.
- Quality over Quantity: include only information that strengthens the professional story.
- Consistency: keep tone, terminology, dates, company names, and formatting aligned across all documents.
- Continuous Improvement: update documents as experience, skills, projects, and positioning evolve.

---

## Writing Style

Use writing that is concise, factual, measurable, and technically accurate.

Prefer active voice. Avoid marketing language, unsupported buzzwords, exaggerated claims, and vague statements. Every strong claim should be supported by evidence, context, or measurable impact.

---

## Preferred Verbs

Use precise action verbs such as:

- Designed
- Implemented
- Developed
- Optimized
- Automated
- Integrated
- Reduced
- Improved
- Built
- Created
- Refactored
- Led
- Mentored
- Investigated
- Analyzed
- Validated

Avoid repeating the same verb many times in one document. Choose verbs that accurately describe the work performed.

---

## Engineering Case Structure

Use the following structure when describing achievements:

- Problem
- Solution
- Result
- Technologies

Whenever possible, include measurable impact.

Example:

Problem:  
Large mobile build size.

Solution:  
Optimized assets and loading pipeline.

Result:  
Reduced iOS build size from 200 MB to 41.7 MB.

Technologies:  
Unity, Addressables.

---

## Metrics

Whenever possible, include measurable values:

- %
- MB
- GB
- ms
- FPS
- $
- team size
- number of projects
- development time

---

## Resume Structure

Recommended order:

1. Header
2. Professional Summary
3. Selected Engineering Cases
4. Core Competencies
5. Professional Experience
6. Technologies
7. Languages
8. Education

---

## Russian and English Versions

Both resumes describe the same experience.

The English version is an adaptation, not a literal translation. Dates, companies, and engineering facts must always remain synchronized between the Russian and English versions.

---

## File Naming

Do not use version numbers in file names.

Git tags are used for releases.

---

## Future Evolution

This guide is expected to evolve together with the repository as the professional profile, document structure, and career materials become more mature.
